# 图谱可用性升级规划（v0.1.1）

> 状态：已确认方案（2025-08-18）
> 范围：解决「词量增长后的可用性」——找词难、图谱拥挤、近义词关系
> 原则：先规划后实施；不动既有数据 schema 的兼容性

---

## 一、要解决的问题

| 问题 | 现状 | 词量增长后的后果 |
|------|------|------------------|
| 找单词费劲 | 全部节点平铺一屏 | 50 词已挤，100/5500 词不可用 |
| 近义词/同义词关系 | 只有 `related` 字段，无结构 | 词越多，关系越乱，图谱会变成毛线球 |
| 图谱拥挤 | 无分层、无搜索 | 结构被节点淹没，失去探索感 |

---

## 二、方案一：近义词/同义词 —— 概念层中转，不直连

### 2.1 决策（已确认）

✅ **近义词不画成图谱里的词对词连线**，而是让一组近义词**共享同一个 Concept 节点**。

### 2.2 为什么不能直连

1. **毛线球效应**：高频词动辄 20+ 近义词，全连会摧毁图谱结构。
2. **语义陷阱**：`choose / select / elect / pick` 都"选"，但语境不同。直连"同义"会强化"可互换"错觉，违背项目理念（word ≠ 等价翻译）。

### 2.3 概念层中转的结构

```
       Concept: "make a choice / 选择"
            /        |        \
       choose     select     pick
```

- 三个词都通过 `root_ids`/新关系挂到聚合概念下，**近义关系是隐式的**（共享概念即相关）。
- 图谱**零新增连线**，永远保持干净。
- 点开任一单词 → 详情面板显示「近义词组」：同概念的其它词 + 语境差异说明。

### 2.4 数据模型改动

**concepts.json** 增加"聚合概念"节点，用 `type: "cluster"` 标记：

```json
{
  "id": "concept-make-a-choice",
  "type": "cluster",
  "concept": "make a choice",
  "chinese": "选择",
  "core_image": "面对几个选项伸出手挑选其中一个",
  "root_ids": [],
  "word_ids": ["choose", "select", "pick", "elect"]
}
```

**words.json**：词条增加可选字段 `synonym_group`（引用聚合概念 id）：

```json
{
  "word": "select",
  "synonym_group": "concept-make-a-choice",
  "synonym_note": "select = 精心挑选；choose 更通用；elect 指投票选举"
}
```

- `synonym_group`：该词所属的近义词组（一个）
- `synonym_note`：该词在组内的语境差异（**关键**——避免等价错觉）

**relations.json**：不新增近义词连线边。

### 2.5 图谱表现

- 聚合概念以 concept 节点形式出现在图谱（可归入"概念"类着色）。
- 词与概念之间已有 `root`/`derived` 边，聚簇概念天然把近义词"吸引"到附近。
- 近义词关系不画线，靠空间邻近 + 详情面板体现。

### 2.6 首批近义词组（v0.1.1 试点 2-3 组）

| 聚合概念 | 包含词（现有数据里可组） |
|----------|--------------------------|
| make a choice / 选择 | choose*、select*、pick*（*需新增词条） |
| make clear / 表达、说清 | express、describe、state* |
| look at / 看 | inspect、spectate*、observe* |

> 首批只试点 2 组，验证体验后再扩展到全库。新增词条归入 v0.2 词库扩展，本版本重点是机制。

## 三、方案二：搜索框 —— 三路搜索 + 定位高亮

### 3.1 功能规格

- **搜索范围**：单词（word）、词根（root）、中文释义（chinese）三个维度同时搜。
- **交互**：
  1. 输入即出下拉建议（匹配排名：前缀 > 包含 > 中文匹配）
  2. 点击建议或回车 → 图谱**定位 + 高亮**该节点（自动缩放平移，弹出详情面板）
  3. 输入中按词根过滤（如输入 `fig` 提示 figur 词根及其词族）
- **无结果**：提示"未收录：xxx"，提供「标记申请添加」按钮（写入一个待办列表，v0.2 处理）。

### 3.2 实现要点（前端）

- 搜索框放在头部（固定）。
- 匹配在 `nodes` 全量数据上做（内存过滤，50/100 词无性能问题，5500 词仍够用——纯 JS 过滤万级节点 OK）。
- 定位 = 把目标节点设为固定坐标（fx/fy → 画布中心）+ zoom 平移过去 + 高亮描边。

## 四、方案三：图谱视图分层 —— 默认粗粒度 + 点击钻取

### 4.1 视图层级（已确认）

```
默认视图：只显示 词根 + 概念 / 聚合概念（干净，一屏可控）
   ↓ 点击某个词根
展开：显示该词根的词族单词（如 figur → figure/configure/figurative/…）
   ↓ 点击其它词根
切换展开
   ↓ 搜索直达
无论展开到哪一层，搜索结果强制显示并定位该单词
```

### 4.2 交互规则

| 操作 | 行为 |
|------|------|
| 初始加载 | 只显示 root + concept 节点 |
| 点击 root | 展开/收起该 root 的 word 族 |
| 点击 concept | 显示该概念关联的 word（或仅弹详情，v0.1.1 先弹详情） |
| 点击 word | 弹详情（已有） |
| 搜索命中 word | 临时展开其 root 并定位高亮 |
| 空白双击 | 重置视图 / 重新布局（已有） |

### 4.3 实现要点（前端）

- 节点增加 `vizVisible` 状态（是否显示），D3 `join` 时按状态过滤，或直接控制 `opacity/display`。
- 展开动画：使用 D3 transition 淡入淡出，保持顺滑。
- 词根节点添加展开指示（⊕/⊖ 或节点边框高亮）。

## 六、验收标准

1. 搜索 `configure`（含中文"配置"）都能一键定位并弹详情。
2. 初始视图干净（约 20 个节点：10 词根 + 10 概念），点击 figur 只展开 figure/configure/figurative/disfigure/configuration。
3. 点开 `select`（若纳入试点）详情显示近义词组及与 choose/elect 的差异。
4. 图谱中看不到任何新增的近义词连线（保持边数 = 70 左右）。
5. validate.py 全部通过；Pages 自动部署成功。
