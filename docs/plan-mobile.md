# 移动端响应式改造规划（v0.1.2）

> 状态：已确认方案（2025-08-18）
> 范围：手机/平板适配，桌面体验保持不变
> 前置：v0.1.1（搜索 + 分层钻取 + 近义词组）已完成
> 注意：本文档只规划，实施前需用户确认

---

## 一、要解决的问题

当前页面是"图谱 + 侧栏"的桌面布局，手机上完全不可用：

| 问题 | 原因 |
|------|------|
| 图谱被挤成一条缝 | `main` 横向 flex：图谱 + 右侧固定 340px 详情栏 |
| 详情面板没法看 | 340px 固定宽度占满小屏，与图谱抢空间 |
| 触屏交互失灵 | 滚轮缩放 / 鼠标拖动在手机上不存在 |
| 搜索框被挤压 | header 标题+搜索框横排，小屏下挤成一团 |
| 图例/提示遮挡 | 底部固定元素占据小屏空间 |

核心矛盾：**桌面是"图谱为中心"，手机是"查词为中心"**——手机上不应靠在一张密集图里找词。

---

## 二、方案（已确认）：响应式改造

### 2.1 布局断点

| 断点 | 布局 |
|------|------|
| ≥ 768px（桌面/平板横屏） | 现状不变：左侧图谱 + 右侧详情栏 |
| < 768px（手机/平板竖屏） | 上下布局：搜索框置顶 → 图谱在上 → 详情变底部抽屉 |

### 2.2 手机端布局（< 768px）

```
┌─────────────────────────┐
│ English Semantic Graph  │  header（紧凑）
│ 🔍 搜索单词/词根/中文…   │  搜索框全宽
├─────────────────────────┤
│                         │
│     图谱（占 ~55vh）      │  双指缩放/单指拖动
│                         │
├─────────────────────────┤
│ 点击节点 → 底部抽屉滑出   │
│ 词源·概念·画面·近义词·例句│  详情抽屉（半屏，可上滑全屏）
└─────────────────────────┘
```

### 2.3 交互适配

| 桌面 | 手机 |
|------|------|
| 滚轮缩放 | 双指捏合缩放（D3 zoom 原生 touch 支持） |
| 鼠标拖拽节点 | 单指拖动（D3 drag 已兼容 touch） |
| 右侧详情栏 | **底部抽屉**：点击节点从底部滑出，半屏可上滑全屏，下拉或点×关闭 |
| 双击空白重新布局 | 保留（双击/双指双击均可用） |
| 图例/提示 | 手机端改为可收起的小按钮（或默认折叠） |

### 2.4 技术要点

- **CSS**：新增 `@media (max-width: 768px)` 断点；`main` 变纵向 flex；`#detail-panel` 手机端变成 `position: fixed` 底部抽屉，带滑入滑出动画。
- **JS**：
  - `render()` 尺寸计算已用 `parentElement.clientWidth/Height`，天然响应式，无需大改。
  - 详情面板手机端切换显示方式：用 CSS class（如 `drawer-open`）控制，不破坏桌面逻辑。
  - D3 zoom 增加 `.touchable()` 确保触屏可用。
  - 抽屉关闭按钮 + 手势（上滑展开/下拉收起，v1 先做按钮版）。
- **尺寸/字体**：手机端字号、节点半径、连线粗细微调，防止密集重叠。
- **viewport**：已有 `<meta name="viewport" content="width=device-width, initial-scale=1.0">`，无需改。

## 三、实施步骤（确认后执行）

| 步骤 | 内容 | 工作量 |
|------|------|--------|
| 1 | CSS：768px 断点 + 上下布局 + 底部抽屉样式（含动画） | 中 |
| 2 | JS：详情面板抽屉化（class 切换 + 关闭按钮）、touch 手势适配 | 中 |
| 3 | 手机端图例/提示折叠处理 | 小 |
| 4 | 小屏下节点/字号/连线密度微调 | 小 |
| 5 | 本地 node 语法检查 + validate.py + 推送部署 | 小 |
| 6 | 线上验证（桌面 + 手机 UA 请求） | 小 |

---

## 四、验收标准

1. 手机宽度（375px）打开：搜索框全宽置顶，图谱占上屏，可双指缩放、单指拖动。
2. 点击任意节点：底部抽屉滑出详情，含词源/概念/画面/近义词组/例句；可上滑查看全文，可关闭。
3. 搜索词直达：手机端同样定位高亮 + 弹抽屉。
4. 桌面端（≥768px）外观与交互**完全不变**。
5. validate.py 通过，Pages 部署成功。

---

## 五、明确不做（本轮）

- ❌ 不做手机端"查词优先"列表模式（词库到几百词后再评估，v0.2+）
- ❌ 不做 PWA / 离线缓存（v0.2 后与内容量一起做）
- ❌ 不重写前端框架（保持原生 D3 + 单页）
- ❌ 不做服务端渲染

## 六、后续演进（v0.2 再评估）

- 词库 >200 词时：手机端增加"查词优先"模式（搜索+列表为主，图谱降级为可选）
- PWA：manifest + service worker，添加到主屏幕、离线可用
- 图谱聚簇布局：按词根自动分组，进一步缓解密集
